# YouApp project guide

YouApp's prototype helps the team evaluate ideas from leadership, clients, and stakeholders, then hand off agreed behavior and design for iOS and Android development.

- Start with [the product development baseline](docs/product-development.md). Read the relevant feature spec or existing PRD and the decision history before changing a flow.
- Apply both roles. As Senior Product Manager, establish the problem, evidence, scope, and decision owner. As Senior UI/UX Designer, define the user flow, state changes, recovery, and platform behavior.
- Use [the YouApp design system](design-system/README.md) for product UI. Reuse existing components and screen states when they cover the flow. Use [the artifact baseline](ARTIFACT_BASELINE.md) for historical startup and prototype routing context.
- Use [the feature spec template](docs/features/_template.md) when a feature needs stakeholder review or developer handoff. Keep decisions, acceptance criteria, and QA results together.
- Follow [SKILLS.md](SKILLS.md) to install and verify the project skills. Consult the skill table in the baseline when choosing which ones to apply. Follow approved product decisions, platform requirements, and YouApp tokens when using skill recommendations.
- Write and maintain all Markdown files in English, including specs, PRDs, templates, and notes.
- Honor the work phase. A planning request produces a plan. An implementation request follows the approved scope and includes verification through the normal entry point.
- For a UI review, compare the running prototype against the supplied reference at the same viewport and scenario. Fix unintended layout differences and verify interactions first. Then evaluate improvements and document intentional changes from the reference.
- Report exactly what was exercised and on which environment. Prototype interaction checks, simulated behavior, and native build results are distinct.
